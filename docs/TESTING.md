# Testing arbitrary tasks

Цель — проверять не набор заранее известных команд, а способность Chat A маршрутизировать произвольную задачу к нужным инструментам и при необходимости использовать Chat B как независимый reviewer.

## Контракт

- Chat A = текущий пользовательский чат, Orchestrator / Executor + Desktop Commander.
- Chat B = отдельный обычный ChatGPT, Planner / Reviewer.
- Пользователь пишет задачу обычным языком, без специального шаблона.
- Chat A сам выбирает инструменты, проверки и необходимость reviewer.
- Простые однозначные задачи не обязаны идти через ping-pong.

## Классы задач

1. Файлы и код — поиск, правки, сборка, тесты, Git.
2. Браузер / web app — навигация, формы, скачивание/загрузка, проверка UI.
3. Desktop GUI — Figma, PowerPoint, Adobe и другие приложения через API/AppleScript/Accessibility/visual fallback.
4. Deploy / server — SSH, GitHub, Vercel, Cloudflare и CLI.
5. Документы и данные — PDF/DOCX/XLSX/CSV.
6. Research / external services — web и connectors.
7. Mixed task — несколько классов в одной цепочке.
8. Voice input — голос становится обычной задачей Chat A.

Новый класс задачи не требует нового master-prompt: сначала инспекция доступных инструментов, затем маршрут.

## Как тестировать дальше

Не делать десятки синтетических тестов. Давать реальные задачи из работы, желательно из разных классов.

Для первых нескольких задач полезно покрыть:
- код + Git + публикацию;
- GUI-приложение;
- браузер + локальное действие;
- документ/таблицу;
- смешанную задачу из нескольких приложений.

После каждой задачи новый устойчивый приём или ограничение фиксируется в GPT-automation.

## Acceptance criteria

Задача считается пройденной, если:
- реальный результат создан или изменён;
- результат проверен подходящим способом;
- публичная публикация проверена фактически, если она входила в задачу;
- reviewer при использовании получил evidence, а не самооценку;
- нет ручного шага, который можно было выполнить инструментами;
- новое системное знание записано в репозиторий.

## Реальные внешние блокеры

Человек всё ещё может понадобиться для TCC permission, пароля/2FA/CAPTCHA, оплаты, юридически значимого подтверждения, заблокированного `sudo` или отсутствующего бизнес-решения. В таком случае Chat A останавливается ровно на блокере и просит один конкретный ручной шаг.
