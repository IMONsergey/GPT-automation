# Two-chat ping-pong orchestration

## Назначение

Получить второй независимый контур мышления/ревью, не выводя пользователя из обычного ChatGPT и не заставляя его вручную переносить сообщения.

## Роли

### Chat A — ORCHESTRATOR / EXECUTOR

Это текущий пользовательский чат.
Он видит исходную задачу, имеет Remote Desktop Commander и реально меняет Mac/проекты.
Он отвечает за фактическую проверку и финальный результат.

### Chat B — PLANNER / REVIEWER

Отдельный обычный ChatGPT-чат в Chrome.
Он не обязан иметь Desktop Commander.
Он получает компактный контекст, предлагает следующий шаг, критикует результат и проверяет соответствие критериям.

Пользователь общается в основном с Chat A.

## Базовый цикл

1. A принимает исходную задачу пользователя.
2. A собирает факты: файлы, скриншоты, код, ограничения.
3. A отправляет B пакет `PLAN_REQUEST`.
4. B возвращает конкретный следующий шаг и критерии проверки.
5. A исполняет шаг через Desktop Commander.
6. A проверяет результат локально.
7. A отправляет B пакет `REVIEW_REQUEST` с фактами, а не самооценкой.
8. B отвечает `PASS`, `REVISE` или `BLOCKED`.
9. При `REVISE` A выполняет следующий цикл.
10. При `PASS` A делает финальную проверку, фиксирует изменения и отвечает пользователю.

Default limit: 8 итераций.
Для рискованных операций A не делегирует окончательное решение B: действует по правилам текущего чата и явной задаче пользователя.

## Формат обмена

Каждое сообщение между чатами должно быть коротким и структурированным.

```text
TYPE: PLAN_REQUEST | REVIEW_REQUEST
ITERATION: N/8
GOAL: ...
CURRENT_STATE: ...
CHANGED: ...
EVIDENCE: ...
CONSTRAINTS: ...
ASK: Give exactly the next actionable step or verdict.
```

Ответ B желательно требовать в формате:

```text
VERDICT: PASS | REVISE | BLOCKED
NEXT_ACTION: ...
CHECK: ...
REASON: ...
```

Не пересылай весь чат. Только сведения, необходимые для текущего решения.

## Транспорт A -> B

Статус: `VERIFIED`.

Проверено 2026-10-02:
- отдельная обычная вкладка ChatGPT найдена/создана;
- composer можно сфокусировать;
- текст передаётся через `pbcopy` + Cmd+V;
- Enter отправляет сообщение;
- B ответил `PING-PONG READY`.

Clipboard предпочтительнее `keystroke` для длинного текста.

## Транспорт B -> A

Статус: `PARTIAL`.

Рабочий fallback внутри агента:
1. активировать B;
2. дождаться завершения ответа;
3. снять screenshot;
4. визуально найти последний assistant response и его Copy action;
5. нажать Copy;
6. прочитать `pbpaste`;
7. проверить, что clipboard изменился и содержит ожидаемый ответ.

Этот fallback приемлем для автономной работы текущего ChatGPT, но требует нескольких tool calls.

## Что не считать готовым inbound API

Попытка включить Chrome `Allow JavaScript from Apple Events` через GUI automation не применилась.
Accessibility tree Chrome в тесте не отдал содержимое web page как удобные AXText nodes.
Прямой координатный Copy без визуальной проверки ненадёжен.

До появления стабильного DOM/CDP/Apple-events канала использовать screenshot + vision + Copy.

## Контроль качества

B не должен писать код/изменения вместо A, если это мешает независимому ревью.
A не должен слепо выполнять мнение B: B — консультант, A — исполнитель и валидатор.
Для дизайна перед ревью давать B актуальный screenshot.
Для кода давать diff/test output.
Для deploy давать URL/HTTP check/build result.

## Условия завершения

Задача завершена только когда:
- функциональные критерии пользователя выполнены;
- A проверил реальный результат;
- нет известных критических ошибок;
- публикация выполнена, если она была частью задачи;
- B дал `PASS` или A документировал, почему независимое замечание неприменимо.

## Защита от зацикливания

Максимум 8 итераций по умолчанию.
Если два раза подряд B повторяет одно и то же замечание без новых фактов, A должен изменить стратегию проверки, а не просто повторять изменение.
Если B просит невозможное из-за отсутствующего доступа, A возвращает фактические ограничения.
Если блокер требует пользовательского секрета, оплаты, TCC-confirmation или бизнес-решения — остановиться и спросить пользователя.

## Именование чата B

Рекомендуемый заголовок: `GPT Automation Reviewer`.
Не создавать новый reviewer-chat для каждой мелкой итерации: переиспользовать один чат в рамках задачи, чтобы он сохранял локальный контекст.
